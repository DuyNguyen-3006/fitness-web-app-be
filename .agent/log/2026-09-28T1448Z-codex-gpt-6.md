# Register user and activity services with Eureka

- Scope: root, user-service and activity-service Maven POMs; activity application YAML and shareable example.
- Root cause: Eureka server was listening on 8761 with an empty registry; user-service YAML pointed to it, but neither user-service nor activity-service declared the Eureka Client starter. Activity had no Eureka URL in YAML and was not running at initial inspection.
- Change: manage Spring Cloud 2025.1.3 at parent, add Eureka Client starter to both services, configure activity's Eureka URL.
- Verification: `mvn -q test` passed 27/27. Live `GET http://localhost:8761/eureka/apps` subsequently listed one UP instance of USER-SERVICE and one UP instance of ACTIVITY-SERVICE. A separate activity startup probe was abandoned because port 8082 became occupied by an active user process; no process was stopped.
- JDK note: IntelliJ Project SDK and observed running Java processes used JDK 26; Maven used JDK 21. User should select JDK 21 in Project Structure and application Run Configuration if they want JDK 26 runtime warnings gone.

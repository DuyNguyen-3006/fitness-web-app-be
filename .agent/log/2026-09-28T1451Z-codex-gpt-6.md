# Localhost Eureka instance host

- Scope: user-service application YAML, activity-service application YAML and shareable example.
- Root cause: Eureka clients auto-detected the OS/network hostname `DESKTOP-CTQF1D1.mshome.net` and IP `172.31.96.1`; `defaultZone=localhost` only tells clients where to find the Eureka server.
- Change: set `eureka.instance.hostname=localhost` and explicit instance IDs `localhost:${spring.application.name}:${server.port}` for both local services.
- Verification: `mvn -q -pl user-service,activity-service -am test` passed 26 tests; a temporary activity Spring context read `host=localhost id=localhost:activity-service:8082` from the bound Eureka config.
- Handoff: active IntelliJ-launched processes still advertise old host; restart user-service and activity-service, then refresh Eureka dashboard. Do not force-stop the user's IDE processes.

# User validation API envelope

- Scope: user controller/service/interface, one HTTP contract test, and activity UserValidationService WebClient consumer.
- Root cause: `/api/users/{userId}/validate` returned raw Boolean despite repo-wide ApiResponse contract; activity WebClient expected raw Boolean.
- Change: service returns `ApiResponse.success("User validation completed", exists)`; controller returns `ResponseEntity<ApiResponse<Boolean>>`; activity client decodes `ApiResponse<Boolean>` and reads `data`.
- Semantics: valid/invalid user IDs both produce HTTP 200 and `success=true`; `data` carries true/false. A missing user is a normal validation result, not a failed HTTP request.
- Verification: clean Maven build `mvn -q -pl user-service,activity-service -am clean test` passed 27 tests. Initial non-clean test run hit stale target classes with missing `UserRepository`; clean build resolved it.
- Handoff: restart any IDE-running user-service/activity-service process to load the new wire contract.

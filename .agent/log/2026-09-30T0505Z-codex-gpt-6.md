# Fix activity validation return type

- Scope: ActivityService, ActivityController, their tests, and UserValidationService test/formatting.
- Root cause: ActivityService assigned `UserValidationService.validateUser` (which returns `ApiResponse<Boolean>`) directly to a boolean. Its new dependency also made existing ActivityService tests instantiate the wrong constructor.
- Change: read `validation.data()` after checking the response is present and successful. An absent user returns ApiResponse error and the POST controller uses HTTP 400 instead of 201. An upstream validation failure throws for the existing 500 handler. Preserved the current UserValidationService try/catch response behavior.
- Verification: `mvn -q -pl activity-service -am clean test` passed 14/14 activity tests, including no-save on invalid user, upstream error, and HTTP status checks.
